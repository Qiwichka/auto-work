# /auto-work: как научить своего Claude работать самому, но не наломать дров

Это шаблон скилла для Claude Code. Ты пишешь `/auto-work`, и Claude сам разбирается, что сделать для твоего проекта: смотрит цифры, выбирает задачи, пишет код. Всё, что уходит людям (сообщения, посты, обещания), он не делает, а собирает в один короткий список и ждёт твоё «да».

Идея в трёх корзинах:

| Корзина | Что внутри |
|---|---|
| Делает сам | читать статистику, писать код в отдельной ветке, проверять, готовить черновики |
| Только после твоего «да» | сообщения людям, публикации, промокоды и обещания, цены |
| Никогда | удалять данные, тратить деньги, публиковать секреты, массовый спам |

Код копится в отдельной ветке и не выходит на боевой сайт, пока ты сам не напишешь кодовое слово. Так Claude может работать без тебя и ничего не сломать публично.

## Установка за 3 шага

1. Положи файл на место (в домашней папке):

```bash
mkdir -p ~/.claude/skills/auto-work
cp SKILL.md ~/.claude/skills/auto-work/SKILL.md
```

2. Открой `~/.claude/skills/auto-work/SKILL.md` и замени все места вида `<<ТАК>>` на своё (таблица ниже). Поиск по `<<` должен ничего не находить, когда закончишь.

3. Запусти Claude Code и напиши `/auto-work`. Если команды нет в списке, закрой и снова открой Claude Code.

## Что подставить

| Место в файле | Что вписать | Пример |
|---|---|---|
| `<<ПРОЕКТ>>` | название проекта | Моя Кофейня |
| `<<ПАПКА_ПРОЕКТА>>` | путь к папке с кодом | `~/projects/coffee` |
| `<<АДРЕС>>` | адрес сайта, если он есть | https://coffee.example.com |
| `<<ГДЕ_ЦИФРЫ>>` | где смотреть статистику | аналитика сайта, таблица в базе |
| `<<ГЛАВНАЯ_ВЕТКА>>` | ветка, которая выкладывается на сайт | `main` |
| `<<ВЕТКА_НАКОПЛЕНИЯ>>` | ветка, куда Claude копит работу | `release-next` |
| `<<КОДОВОЕ_СЛОВО>>` | слово, которым ты разрешаешь выкладку | придумай своё, не простое |
| `<<ТВОЁ_ИМЯ>>` | как к тебе обращаться в пинге | Вася |
| `<<КОМАНДА_ОТПРАВКИ>>` | команда, которая шлёт тебе сообщение на телефон | свой телеграм-бот |

Если отправка на телефон тебе не нужна, удали из файла раздел «Пинг» и строку про отправку в «Где что лежит».

## Как подогнать под себя

- Не публикуешь посты? Убери пункт про публикации из списка «по «да»».
- Нет сайта и выкладок? Убери из файла всё про главную ветку и кодовое слово, оставь коммиты в ветку.
- Хочешь строже? Перенеси пункт из корзины «сам» в «только по «да»». Хочешь вольнее: наоборот, но корзину «Никогда» не трогай.
- Хочешь другой язык ответов? Поменяй строку «Пиши пользователю по-русски».

## Как не облажаться

- Первый запуск делай на небольшом проекте и сразу смотри, что Claude положил в ветку накопления.
- Не вставляй в `SKILL.md` пароли, токены и ключи. Файл читает модель, а если выложишь его на GitHub, прочитает весь интернет. Секреты держи в отдельных файлах вне репозитория.
- Перед публикацией своего скилла просмотри его целиком: имена людей, адреса, id проектов и кодовые слова там быть не должны.
- Строка `disable-model-invocation: true` в начале файла нужна, чтобы скилл запускал только ты командой `/auto-work`, а не сам Claude по своему решению.
